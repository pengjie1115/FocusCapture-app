# 飞书（桥接官方 lark-cli）

你通过 `scripts/lark.py` 把参数**原样转发**给官方 `lark-cli`。

**本文件里没有任何飞书业务知识** —— 那是官方维护的，随 CLI 版本更新。你要做的是按下面的顺序**去读**，再照着转发命令。

## 动手顺序（别跳步）

1. **看有哪些域**：`args=["--help"]`
2. **看某个域有哪些命令**：`args=["<域>", "--help"]`
   - 要查一个具体接口的参数与所需权限域：`args=["schema", "<service.resource.method>"]`
3. **读该域的官方技能**（这才是"怎么用对"的知识）：`args=["skills", "read", "<技能名>"]`
   - 名字规律是 `lark-<域>`，例如 `lark-base`（多维表格）、`lark-doc`、`lark-sheets`、`lark-wiki`、`lark-im`、`lark-mail`、`lark-calendar`、`lark-task`
   - **`lark-shared` 讲授权与身份（`--as`）、权限域、缺权限怎么办 —— 动手前先读它**
   - `lark-openapi-explorer` 用来挖 CLI 还没封装的原生接口
4. 再用 `lark.py` 转发真正的命令

调用形态（args 的每一项原样成为 lark-cli 的参数，不经过 shell，引号空格不用你操心）：

```
run_skill_script(skill="lark-cli", script="lark.py", args=["skills", "read", "lark-shared"])
```

- **优先用官方的高层快捷方式**（命令名以 `+` 开头那类），没有对应的再用逐接口命令
- 需要用户身份时按 `lark-shared` 的说明加 `--as user`

## 输出会被截断 —— 这是硬约束

工具返回的是**退出码 + stdout + stderr 原文**，但内容**只保留头尾、中间会被砍掉**（上限约 4000 字）。所以：

- **不要**一上来跑 `args=["skills", "list"]`：它是 JSON，实测 **12,844 字**，必被截断，还白烧 token。要"有哪些域"就先 `args=["--help"]`（实测 3,663 字，完整）
- 大结果一律收窄：API 类命令用 `--jq '<表达式>'` 只取需要的字段；先加 `--dry-run` 预演请求（不会真的执行），确认参数对了再真跑
- 要读某个技能附带的参考文件：先 `args=["skills", "list", "<技能名>"]` 看它有什么（像 ls），再 `args=["skills", "read", "<技能名>/<相对路径>"]` 读那一份
- 要传很长的 JSON 参数，用工具的 `stdin` 参数（脚本会把它转交给 lark-cli）

## 风险分级（cli 自己标的，照它走）

每个命令的 `--help` 都会标出 `Risk: read | write | high-risk-write`：

| 级别 | 怎么处理 |
|---|---|
| `read` | 直接做 |
| `write` | **先跟用户说清要做什么，等他确认** |
| `high-risk-write` | 必须在用户确认之后加 `--yes` 才会真正执行 |

## 纪律（硬要求）

1. **写操作与高危操作之前，先向用户说明要做什么、等他确认。** 发消息、发邮件、创建/修改/删除文档与文件、改表格数据、提交审批都算；只读查询可以直接做。
2. **绝不把命令、终端步骤、安装路径写进给用户的回复里。** 用户不需要、也不该去敲命令 —— 所有事都由你在应用内完成。
3. 失败就**照实说**（把关键错误原样转达）。不要假设成功，不要编造结果，也不要把"登记成功"说成"已同步到飞书"。
4. 遇到未授权或缺少依赖：如实告诉用户需要先在应用里完成授权，位置是「设置 → AI 功能 → Skill 扩展」。**不要另想替代路径去绕过授权。**
5. 用户的密钥、token 之类的凭据，**不要写进任何输出、笔记或文件**，也不要显示给他看。
6. 结果里若含隐私内容（邮件、聊天记录、联系人），只汇报任务相关的那部分。

## 这个 Skill 的边界

- `lark.py` 只是转发壳，里面没有业务逻辑 —— 改它没有意义
- 某个 Skill 首次执行脚本时，应用会先问用户一次是否允许
- 它依赖外部程序 lark-cli 与应用自带的 Python：**缺了由应用负责准备，你不用管**，也不要建议用户自己去装
