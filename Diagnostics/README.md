# Diagnostics — 界面快照工具

> 2026-09-13 引入。定位：**降低界面问题的发现成本**，不是替代判断。

## 它解决什么问题

有些界面问题**静态代码完全看不出来**，只有渲染出来才知道：

| 类型 | 例子（都是本项目真实踩到的） |
|---|---|
| 控件被挤出可视区 | 设置页「移除」按钮超出面板宽度，被裁得一个像素都不剩，用户以为功能不存在 |
| 图标字形缺失 | 图标字符换成矢量字体后，某几个码位在该字体里没有字形，渲染成空框（豆腐块） |
| 文字与背景对比度过低 | 列表项文字亮度 55、背景亮度 37，几乎融在一起，用户反馈"看不太清楚" |
| 图标基线偏位 | 文本类符号（`⟳` / `□`）在按钮里不居中，或笔画缺失（箭头丢失） |

这些用肉眼或截图像素分析一看便知，但**必须先能看到**。本工具负责把图摊开。

## 怎么用

```bat
REM 生成全部已注册窗口的快照（默认输出到 %TEMP%\fc-ui-snapshot）
bin\Debug\net8.0-windows\FocusCapture.exe --snapshot

REM 指定输出目录
bin\Debug\net8.0-windows\FocusCapture.exe --snapshot --out D:\shots
```

输出内容：

- `NN-窗口名.png` —— 每个窗口一张，按窗口实际 DPI 出图（125% 缩放也准确）
- `snapshot.log` —— 每个窗口的**实际像素尺寸**。尺寸异常 = 布局异常的第一信号（例如本该 760×620 的窗口只有 110×60）

配套子工具：

- **`12-图标字符可用性自检.png`** —— 把一批候选图标码位用**与标题栏图标钮完全相同的样式**渲染出来。
  挑图标代码时先跑它：**字体文件里有 ≠ WPF 渲染得出来**，猜代码必踩空框。有图形 = 可用，空框 = 该码位无字形。

**加新场景的原则**：状态相关的界面（空态、满态、禁用态）需要**单独造场景**，
默认状态往往走不到那些分支（例如"下拉为空"只有在功能池全部启用时才出现）。

## 设计约束（改本工具前必读）

1. **数据隔离**：强制把 `FocusCapturePaths.RootOverride` 指向临时沙箱，绝不读写用户真实的
   `%AppData%\FocusCapture`，沙箱用完即删。
2. **零侵入**：仅在显式传入 `--snapshot` 时执行。正常启动（不带该参数）不进入此分支，
   行为与改造前完全一致 —— `App.xaml.cs` 里只有一处 `if (UiSnapshot.IsRequested(e.Args))`。
3. **必须 `Show()` 才能渲染**：窗口统一摆到屏幕外（`Left/Top = -32000`），不打扰用户。
4. **不透明渲染**：灵感速览面板本身 `Opacity=0.8`，半透明位图不利于像素比对，快照统一置为 `1.0`。
5. **单个窗口失败不影响其余**：每个窗口独立 try/catch，失败只记进 `snapshot.log`。

## 判读建议

- **不要只看整体缩略图** —— 图标偏移、字形残缺在缩略图上看不出来，要**放大裁剪**再看。
- **对比法最有效**：改动前后各跑一次，同区域裁剪出来并排看。
- **像素采样可量化**：文字对比度这类问题，取区域内的最亮像素与背景色比亮度，能给出硬数字
  （本次「文字看不清」就是靠这个定为"文字亮度 55 / 背景 37"才敢下结论的）。
